# PROMPT FOR CODEX

Работай с уже существующим моим сайтом. Реализуй в подходящей существующей секции эффект прокрутки пространственной спирали карточек по техническому описанию ниже.

Единственный визуальный референс: https://pacomepertant.com/.
Нужна только спираль: её геометрия, прокрутка, инерция, изгиб карточек, глубина, hover и связанные подписи. Вступление, экран входа со звуком и режим list референса не входят в задачу. Не добавляй их. Не используй другие сайты как визуальные референсы.

1. Сначала изучи существующий проект

Прочитай AGENTS.md и инструкции проекта. Разберись в структуре репозитория, стеке, роутинге, компонентах, текущей галерее, источнике данных, стилях, обработке прокрутки, адаптиве, доступности и командах проверки. Прочитай связанные компоненты и установленные зависимости до изменения кода.

Не переписывай сайт с нуля. Сохрани тексты, изображения, логотипы, маршруты, структуру и работающую функциональность. Выбери существующий блок работ/кейсов для улучшения; не перестраивай ради эффекта весь сайт. Используй настоящие записи проекта. Повторять их для непрерывной визуальной петли можно, создавать вымышленные работы нельзя.

Не копируй чужие тексты, изображения, логотипы, аудио, декоративные иллюстрации, Lottie или исходный код референса. Напиши собственную реализацию описанной модели. Сохрани брендинг моего сайта.

Используй текущий стек. Если Three.js уже установлен, используй его. Если движка нет, прямой Three.js является обоснованной зависимостью для требуемых деформаций и двух сторон карточки. Не добавляй React Three Fiber, GSAP, Lenis, ScrollTrigger или другую обвязку только ради этой сцены. Без зависимости реализовать точные шейдерные деформации через CSS невозможно; CSS 3D допускается только как упрощённый fallback.

2. Архитектура

Сделай переиспользуемые части с подходящими проекту именами:
- SpiralGallery: контейнер, данные, семантическая навигация, fallback.
- SpiralScene: камера, renderer, геометрия, материалы, текстуры, resize/dispose.
- SpiralInput: wheel, pointer/touch, управление скоростью и фазой.
- SpiralCaption: DOM-подпись наведённой/выбранной карточки.
- Настройки движения и адаптива в одном объекте.

Контракт данных: id, title, image, href/onActivate. Повторные визуальные экземпляры ссылаются на исходную запись; доступные ссылки содержат каждую работу один раз. Состояние движения храни вне покадровых React/Vue re-render. DOM обновляй при смене выбранной работы.

3. Геометрия спирали — основные параметры референса

Все координаты ниже заданы в мировых единицах, углы в радианах.

PerspectiveCamera:
- position = (0, 0, 8), направление на (0, 0, 0).
- FOV = 35° при ширине сцены >= 900 px; 45° при ширине < 900 px.
- near = 0.1; far = 100; aspect = ширина / высота контейнера.
- Камера неподвижна: не добавляй следование мыши, rotateX/rotateY от курсора или OrbitControls.

Карточки:
- Общая PlaneGeometry(1, 1, 8, 8).
- Scale = (1.7, 1.0, 1.0). Геометрическое отношение сторон 1.7:1.
- Радиус R = 2.
- Угловой шаг A = 0.85 rad, приблизительно 48.7°.
- Вертикальный шаг H = 0.5.
- Смещение по Y = -0.8.
- Материал двусторонний; текстура заполняет плоскость по принципу object-fit: cover.

Пусть phase — непрерывная фаза движения в шагах карточек; N — количество визуальных экземпляров, i — индекс экземпляра.

wrapped = ((i - phase) % N + N) % N
q = wrapped - floor(N / 2)
angle = q * 0.85

position.x = cos(angle) * 2
position.y = q * 0.5 - 0.8
position.z = sin(angle) * 2
rotation.y = -angle + PI / 2
rotation.x = 0
rotation.z = 0

Нормаль лицевой стороны направлена наружу от оси спирали. Масштаб не меняется от глубины вручную: разные видимые размеры создаёт перспективная камера. Нельзя заменить эту модель вращением всего плоского контейнера.

В исходном референсе 9 работ представлены 18 плоскостями: массив повторён дважды. У нас число повторов вычисляй по размеру фрустума и вертикальному размаху. Перенос экземпляра с одного края петли на другой должен происходить за пределами видимой области вместе с размером карточки и запасом, иначе возникнет скачок. Не ограничивайся двумя копиями при малом количестве работ. Текстуры повторных экземпляров переиспользуй.

Если реальных работ мало, повторяй существующие работы только как визуальную петлю и сохраняй их идентичность. Для одной работы используй её повторяемые экземпляры без вымышленных названий; доступная навигация содержит одну запись.

4. Прокрутка и инерция

Это wheel-driven сцена с накопленной фазой, а не привязка к window.scrollY, IntersectionObserver или проценту чтения страницы. Не подключай smooth-scroll для этой задачи.

Модель референса на одном шаге симуляции 60 Hz:

onWheel(deltaPx):
  targetSpeed += deltaPx * 0.00015
  targetSpeed = clamp(targetSpeed, -2, 2)
  direction = sign(deltaPx), если deltaPx != 0

tick60Hz:
  speed += (targetSpeed - speed) * 0.1
  phase += speed
  если abs(targetSpeed) < 0.002:
    targetSpeed = direction * 0.002
  targetSpeed *= 0.9

Положительный deltaY увеличивает phase; q и мировая координата Y карточек уменьшаются. Направление вращения меняется вместе со знаком ввода. Во время движения совмещаются обход оси, вертикальное перемещение и поворот самой карточки.

После прекращения ввода обе скорости сглаживаются, но в референсе спираль не останавливается: остаётся примерно 0.0018 шага карточки за кадр при 60 Hz, то есть 0.108 шага/с. Она движется в последнем направлении. Не добавляй snap по умолчанию, отскок или возврат к начальному phase.

Реализуй независимость от частоты дисплея. Для точного повторения этой модели используй фиксированную симуляцию 60 Hz, аккумулятор времени и интерполяцию phase между соседними шагами при отрисовке. Ограничь dt после задержки/возвращения вкладки до 50 ms; не догоняй пропущенные секунды. Не выполняй больше трёх шагов симуляции за render frame.

Эквивалент lerp 0.1 для параметров вне фиксированной симуляции:
alpha(dt) = 1 - pow(0.9, dt / 16.6667).
Постоянная времени одного фильтра около 158 ms; duration у прокрутки не фиксирован. Не подменяй её CSS transition 600 ms. Верхний clamp 2 — защитная граница исходной модели, не желаемая обычная скорость.

Нормализуй WheelEvent.deltaMode: pixels как есть, lines через актуальную высоту строки или 16 px, pages через высоту контейнера. Не перехватывай wheel глобально. Не блокируй прокрутку страницы бессрочно: обрабатывай события только над активной сценой. Если сцена встроена в длинную страницу, её wheel-handler оставляй passive; страница должна продолжать прокручиваться. При необходимости объясни выбранный компромисс локального управления в итоговом отчёте.

Добавь доступную кнопку паузы автоматического движения. На keyboard focus останавливай idle, сохраняя возможность выбора кнопками. При выключенном idle не применяй минимальную скорость0.002: targetSpeed и speed должны затухать до0. При выходе сцены из viewport, открытии перекрывающего UI и document.hidden останавливай rAF. Возобновление не должно прыгать по phase. prefers-reduced-motion полностью отключает непрерывное движение.

5. Деформации карточки — три отдельных слоя

Реализуй собственный vertex shader, не копируя бандл референса.

А. Постоянный изгиб полотна в локальных координатах:
local.z = sin(uv.x * PI) * 0.2.
Края по X остаются на z=0, середина выдвигается на 0.2. Плоскость изгибается, её нельзя воспроизвести одним rotate.

Б. Искривление общего силуэта сцены:
после model transform и view transform прибавь к viewPosition.x:
pow(worldY, 2) * 0.1.
В референсе worldY взят до локального изгиба. Это сдвигает верх и низ сцены вправо сильнее центральной области. Не добавляй симметричный наклон всей камеры.

В. Изгиб от скорости:
viewPosition.x += sin(uv.y * PI) * speed * 2.0.
Используй speed в шагах/кадр при 60 Hz из описанной симуляции. При использовании скорости в шагах/с дели её на 60 для этого uniform. Смена направления меняет знак изгиба. По мере затухания скорости он ослабевает; при включённом автоматическом ходе остаётся очень маленький изгиб.

Здесь нет временного motion blur, trail предыдущих кадров или физического spring. Не добавляй эти эффекты.

6. Материал и две стороны

Лицевая сторона: исходная фотография/превью нашего проекта, cover UV, без изменения контента. Без hover zoom=1, затемнение=0.

Обратная сторона: та же текстура, пространственное усреднение 3x3 с весами:
1 2 1 / 2 4 2 / 1 2 1, сумма 16.
Расстояние соседней выборки по UV = 40/1024, примерно 0.03906. Это размытая изнанка, а не прозрачное стекло. Не добавляй RGB split, отражения, физические lights или видеотекстуры.

Rounded rectangle через SDF/alpha:
- Радиус 0.05 в UV.
- Сглаживание границы порядка 0.002 в UV; допускается fwidth для устойчивости.
- Transparent материал без тяжёлого CSS blur на canvas.

Не ломай передачу цвета текстур: проверь актуальные для установленной версии Three.js настройки colorSpace, финальный вывод цвета и отсутствие двойной gamma-коррекции. Сделай явную устойчивую стратегию depth/прозрачности, чтобы пересечения и углы карточек не создавали прямоугольных артефактов.

Опциональный второстепенный слой, подтверждённый кодом: цвет карточек на верхних/нижних 20% экрана плавно смешивается с #444. Центральные 60% остаются без этого смешивания. Это цветовой edge fade, не исчезновение через opacity. Если такой край нужен для композиции нашего блока, реализуй его в shader без отдельной цепочки тяжёлого постпроцессинга; проверь результат на перекрытиях. Сохрани текущий фон сайта; собственная тонкая статичная сетка допустима только если совместима с брендингом. Не переносить SVG-фон референса.

7. Hover и подпись — только hover:hover и pointer:fine

Курсор используется для raycasting. Он не притягивает карточку, не меняет камеру и не управляет phase. Выбирается ближайшая видимая лицевая сторона.

Hover progress h: 0 -> 1, mouseleave 1 -> 0.
alphaEnter(dtMs) = 1 - pow(0.91, dtMs * 0.2).
alphaLeave(dtMs) = 1 - pow(0.93, dtMs * 0.2).
На 60 Hz это приблизительно 0.27/0.215 за кадр; около 159/206 ms до 95% результата.

На лицевой стороне:
- textureZoom = 1 + 0.05*h.
- blackMix = 0.55*h.
- roundedMaskSize = 1 - 0.05*h.
- Геометрический scale остаётся (1.7,1,1), дополнительного rotate нет.

На mouseleave восстанови zoom=1, blackMix=0, maskSize=1 с указанным сглаживанием. При уходе курсора из canvas очисти hover сразу; не оставляй устаревшую позицию луча.

Hit-test должен учитывать видимый изгиб и прозрачные углы. Используй отражение формул shader в raycast/proxy-геометрии для кандидатов и проверку UV-маски. Обратная сторона не активирует проект. Click по карточке вызывает существующий href/onActivate, без нового роутера или подмены URL.

Подпись — DOM, position:absolute внутри секции, центр по X, bottom:60 px на desktop. Используй название и миниатюру нашей работы. Пример: thumbnail48x48, radius9; контейнерradius14, padding6px 16px 6px 6px, gap12px, текст18px weight500. Не меняй типографику всего сайта.

Появление: translateY(18px) scale(0.96), opacity0 -> translateY(0) scale(1), opacity1; 350 ms.
Исчезновение: translateY(0) scale(1), opacity1 -> translateY(-12px) scale(0.96), opacity0; 250 ms.
Easing = cubic-bezier(0.22,1,0.36,1). Delay=0, stagger отсутствует.
Эти enter/leave применяются при появлении/исчезновении hover. При переходе напрямую между двумя наведёнными работами меняй текст/thumbnail без нового вылета всей плашки.
Анимируй только transform/opacity, не transition:all. Подпись относится к наведённой карточке, а не автоматически к самой большой карточке сцены.

8. Touch и адаптив — предлагаемые улучшения, не утверждение о поведении референса

Исходная мобильная механика: горизонтальный drag, порог8px; targetSpeed += dx * 0.0015; при отпускании добавляется последний dx * 0.001. Tap открывает лицевую карточку. В референсе камера получает FOV45 при ширине<900, но R и размер карточек не меняются.

Наша реализация должна сохранять вертикальный скролл и pinch zoom:
- Pointer Events; touch-action:pan-y pinch-zoom.
- Начинай drag при abs(totalDx)>8px и abs(totalDx)>1.2*abs(totalDy).
- До этого не отменяй обычный tap; при вертикальном жесте не захватывай движение.
- Используй временно нормализованную скорость последних примерно80ms для release inertia, чтобы она не зависела от частоты pointermove. Эквивалент вклада dx*0.001 применяется к оценке смещения за16.67ms.
- Обработай pointercancel, потерю capture, resize, второй палец и blur.
- После drag не открывай проект; tap допускается только при движении <=8px и без cancel.
- Курсорный hover на touch отключён. Подпись и доступная кнопка открытия относятся к явно выбранной работе. Добавь кнопки prev/next, не полагайся только на жест.
- Автоматический idle на touch выключен; инерция должна затухать до0. Это осознанная адаптация.

Стартовые параметры responsive:
- >=1024 px: R2, card1.7x1, gapY0.5, cameraZ8, FOV35, curvature0.1, speedBend2; DPR<=1.5.
- 768–1023 px: те же геометрические параметры; FOV35 при>=900, FOV45 при<900; DPR<=1.5. Hover определяется возможностью устройства.
- <768 px: R1.2, card1.25x0.735, gapY0.45, cameraZ7, FOV45, centerY=-0.65, curvature0.06, speedBend1.2; DPR<=1.

Проверь реальные проекции и подстрой fit, если ближайшая лицевая карточка не занимает примерно45–65% ширины телефона. Частичное обрезание дальних карточек допустимо внутри секции, горизонтальный overflow документа недопустим. Используй размер контейнера, а не только window.innerWidth. На 375/390/430 px оставь подписи и кнопки в safe area, размер цели не меньше44px.

9. Доступность, fallback и производительность

Визуальный canvas не заменяет настоящие ссылки и заголовки. Сохрани семантическую галерею/навигацию с уникальными работами; canvas можно aria-hidden=true. Keyboard: кнопки prev/next, открытие по Enter, видимый focus, без ловушки Tab. Focus может выбрать связанную плоскость; останови auto-motion во время клавиатурной работы. Не включай aria-live для непрерывного движения.

prefers-reduced-motion: существующие неподвижные карточки/ссылки, без автопрокрутки, inertia, деформации от скорости и анимированного подлёта подписи. Все работы и переходы доступны.

Без WebGL, при context loss, ошибке текстуры или выключенном JS сохраняй доступный контент. Ошибка renderer не должна падать на всю страницу. Не создавай WebGL глобально на каждом маршруте. При context loss переключайся на статичные карточки; восстановление только если корректно обработано.

Один rAF-loop сцены, без setState на каждом кадре. ResizeObserver — только при изменении размеров. Переиспользуй геометрию и текстуры. Начни с изображений512px; на mobile256–512px, увеличивай разрешение только по реальной экранной проекции. Заранее готовь ближайшие видимые текстуры, остальные загружай по необходимости; ошибка одной картинки не блокирует остальные.

Отключи shadow maps, физическое освещение, ненужный postprocessing, CSS backdrop-filter и full-canvas blur. Останавливай loop вне viewport/в скрытой вкладке. IntersectionObserver допустим только для этой остановки/ленивой инициализации, не как драйвер спирали.

Удаляй listeners, ResizeObserver, IntersectionObserver и rAF при unmount. Dispose shared geometry/texture только один раз, материалы отдельно. Не накапливай WebGL-контексты после переходов. GPU acceleration не считается гарантией60FPS — проверь на реальном устройстве.

10. Проверка и завершение

Выполни существующие build/lint/typecheck и релевантные проверки проекта. Проверь:
- desktop1440+, laptop1280, tablet768/900/1024, mobile375/390/430;
- wheel мыши и trackpad, deltaMode, смену направления, затухание и idle;
- независимость скорости от60/120/144Hz;
- отсутствие видимого скачка в cyclic wrap;
- форму карточек и знак деформации при смене направления;
- front/back, hover, прозрачные углы, точность клика и mouseleave;
- touch drag/tap/cancel, вертикальный скролл и pinch zoom;
- keyboard, focus, reduced-motion и кнопку паузы;
- WebGL fail/context loss, медленные и ошибочные изображения;
- console errors, runtime errors, overflow, CLS и возврат назад по роутеру;
- FPS/frame time и память при длительной прокрутке и повторных переходах.

Цель на обычном desktop — близко к60FPS, кадр около16.7ms; при нехватке производительности сначала снижай DPR/разрешение и сложность обратной стороны. Не заявляй измеренные FPS или мобильное тестирование, если их не выполнил.

После реализации кратко сообщи: где интегрирован эффект, что изменено, какие параметры совпадают с моделью, какие адаптации сделаны, что проверено и какие проверки недоступны. Доведи задачу до работающего результата в существующем проекте.
