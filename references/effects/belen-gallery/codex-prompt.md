Инструкция для Codex

Самодостаточное задание для независимой реализации. Технический референс: https://www.belenjones.com/. Проверка опубликованного кода выполнена 5 октября 2026 года. Визуальный playback референса не проверен: исследовательский браузер не смог создать WebGL context. Параметры исходной механики ниже установлены по коду; улучшения управления, fallback и доступности являются требованиями адаптации.

Задача и ограничения

Сделай интерактивную проектную галерею с пространственным переключением граней и согласованным DOM-интерфейсом. Используй существующий стек проекта; сначала прочитай его инструкции и структуру. Если проекта нет, подготовь минимальную React/TypeScript-реализацию с Three.js и GSAP. Не устанавливай одновременно несколько анимационных систем. Не копируй контент, бренд и медиа Belen Jones; создай нейтральные демонстрационные данные. Не публикуй и не меняй внешние сайты.

Результат должен содержать рабочую страницу, отдельный конфиг движения, читаемую модель состояний, CSS для desktop/mobile/reduced-motion, fallback без WebGL и короткий README с запуском и проверками.

Модель данных и слои

Project = {id, title, summary, role, tags, image, video?, href?, accent}. ID стабилен и не зависит от физической грани.

1. Layout-слой: размер сцены, безопасные поля, DOM-навигация, текст, кнопки.
2. Scene-слой: камера, группа граней, материалы и соответствие logical project → physical face.
3. Motion-слой: один владелец transform каждого объекта; таймлайн перехода, параллакс, раскрытие.
4. Input-слой: wheel, pointer, keyboard, touch; всё преобразуется в команды next/prev/open/close, не пишет transforms напрямую.
5. Resource-слой: статичные превью, ленивое видео, cleanup, обработка отказа.

Не добавляй опциональный Space+physics drag в первую версию: это вторичный эффект. Предусмотри отдельный флаг для него; основная галерея должна быть закончена без физического движка.

Не рендери обычный текст в WebGL только ради эффекта. Сохрани доступные заголовки, ссылки и кнопки в DOM. Canvas декоративный относительно DOM-структуры.

State machine

- BOOT: загрузить только минимальные ресурсы текущей и соседних работ; интерфейс не ждёт все видео.
- IDLE(index): активная работа, доступны next/prev/open.
- TURNING(from, to, direction): единый переход к соседнему проекту. Повторный wheel внутри того же жеста игнорировать; допустимо запомнить максимум одну следующую явную команду.
- OPENING(index): перелистывание заблокировано, текущая работа раскрывается.
- DETAIL(index): обычная прокрутка контента проекта, действия prev/next не перехватывают её.
- CLOSING(index): возврат к тому же выбранному проекту и положению фокуса.
- FALLBACK: доступный статичный список/слайдер, если WebGL не поддерживается, потерян контекст или загрузка сцены завершилась ошибкой.

Событие resize не должно сбрасывать index. Смена breakpoint должна отменять текущую анимацию, вычислять корректное конечное состояние, освобождать старые слушатели и переинициализировать только сценический режим. Escape закрывает detail, после закрытия фокус возвращается на кнопку открытия. Кнопки prev/next и клавиатура обеспечивают полный альтернативный путь без мыши.

Геометрия и движение: рекомендуемая базовая модель

Обозначения: OuterGroup соответствует группе H, innerGroup — группе k исходника. В формулах логический шаг k является числом; в коде назови его step, чтобы не путать с объектом группы. V — дополнительная внешняя группа для вступления.

Создай четыре плоскости вокруг X-оси, расположенные front/top/back/bottom. Задай их явно: front position(0,0,h/2), rotation.x=0; top position(0,h/2,0), rotation.x=−π/2; back position(0,0,−h/2), rotation.x=π; bottom position(0,−h/2,0), rotation.x=π/2. Проверь направление нормалей и ориентацию видео на каждой плоскости: верх/низ не должны случайно показывать перевёрнутый материал после поворота. Используй PlaneGeometry, не обязателен BoxGeometry. Нельзя создавать девять геометрических граней только потому, что в списке девять проектов: переиспользуй четыре физических слота.

Для логического шага k целевой поворот innerGroup.rotation.x = k·π/2. OuterGroup хранит общий наклон и положение. Поскольку k может возрастать, не нормализуй угол посреди таймлайна. После завершения безопасно нормализовать его на кратное 2π, сохранив отображение индексов. Для перехода назад используй корректный positiveModulo: ((n % count) + count) % count.

Пусть u = clamp((time - start)/duration, 0, 1). Для соответствия найденному коду используй GSAP power2.inOut и duration = 0.9 s на один шаг; theta(u) = mix(theta0, theta1, easing(u)). Для прыжка на jump шагов duration = min(0.9+(jump−1)·0.25, 2.5). Не добавляй второй сглаживающий фильтр поверх таймлайна.

Не добавляй на desktop незапрошенное уменьшение в середине обычного поворота, подпрыгивание, пружину или завал всех осей. Mobile shrink — отдельная подтверждённая механика, не повод переносить её на desktop.

Используй перспективную камеру. Для близкой механики начни с FOV 45°, camera (0,2.5,9), OuterGroup position (0,−0.5,−5), rotation (0.25,−π/6,0), scale 1.5555556, face 6.4×4. Это исходные параметры, не адаптивный закон для всех viewport. При необходимости подбери distance аналитически: distance = visibleHeight/(2·tan(fovY/2)), учитывая aspect ratio и максимальную глубину вращающейся фигуры. Сначала обеспечь правильный размер фронтальной грани и отсутствие обрезания в середине оборота, затем подбирай перспективу. Не меняй одновременно fov и distance на каждом кадре.

Скролл и курсор

В точной базовой механике: |deltaY|≥5 запускает ±1 step, input lock держится до onSettled + 350 ms. Это можно воспроизвести напрямую. Для более устойчивой адаптации к разным трекпадам применяй следующий улучшенный вариант: на desktop одна законченная команда wheel должна означать один переход, а не один поворот на каждое событие браузера. Нормализуй deltaMode в пиксели, накапливай deltaY, используй порог примерно 45 px и dead zone. Сброс накопления после паузы около 140 ms; запрети повторный триггер инерционного хвоста до завершения перехода и нового жеста. Значения должны быть вынесены в конфиг. Перехват допустим только внутри интерактивной галереи, никогда внутри detail и скроллируемых панелей.

В оригинальном hover такой параллакс не обнаружен. Для близкого воспроизведения оставь его выключенным. Если арт-дирекция новой работы отдельно требует pointer-параллакс, это отдельный необязательный слой, не источник переключения. Нормализуй pointer относительно контейнера: nx = 2·(x-left)/width-1, ny = 2·(y-top)/height-1. Рекомендуемый предел yaw ±2°, pitch ±1.5°. Сглаживание, независимое от частоты: a = 1 - exp(-dt/tau), current += (target-current)·a, tau ≈ 0.12 s. На pointerleave плавно верни target к нулю. Если референс требует фиксированной камеры, оставь коэффициенты нулевыми. Отключи на coarse pointer и reduced-motion.

Click не должен открывать проект после drag. Запоминай pointerdown, считай смещение; при превышении 8 px отменяй click/open. DOM-кнопки работают независимо от raycast. Кастомный курсор никогда не должен быть единственным носителем подсказки; на touch он отсутствует.

Кадрирование, маски, раскрытие

Для заданных выше camera/geometry вычисляй q=tan(22.5°), A=viewportWidth/viewportHeight, w=faceWidth, h=faceHeight; coverScale=1.08·max(28q/(h+hq),28qA/(w+hqA)). Эта формула привязана к данной камере; после её изменения пересчитай покрытие по проекции.

Медиа заполняет грань по правилу cover без растяжения. Для frameAspect f = frameWidth/frameHeight и mediaAspect m = mediaWidth/mediaHeight: если m > f, samplingWidth = f/m и samplingHeight = 1; иначе samplingWidth = 1 и samplingHeight = m/f. UV центрируй и умножай на эти коэффициенты. Для DOM-постера используй object-fit: cover.

Граница самого viewport — обычный overflow: hidden. Граница прямоугольной плоскости — её геометрия/UV; shader mask нужна только при реальном эффекте нестандартного reveal, не по умолчанию. Следи за near/far camera clipping и backface visibility. Не путай исчезновение оборотной стороны с CSS clip-path.

Для соответствия источнику сначала анимируй H за .65 s power3.inOut к rotation(−.278,0,0), scale=coverScale, y=baseY−.6; после этого открой отдельный DOM overlay. При закрытии возвращай H за .5 s power2.inOut. Синхронизируй время видео; не представляй этот переход как mesh→HTML morph. Упрощённая альтернатива, если WebGL-раскрытие не нужно: fade сцены и DOM-панели за .55 s. Не вводи FLIP/morph mesh→HTML без отдельного требования. Не анимируй layout/измерения в каждом rAF. Close должен быть обратимым при resize и медленной загрузке видео.

Mobile, доступность, reduced motion

Мобильный режим должен быть самостоятельным. Для близкого воспроизведения используй нативную вертикальную прокрутку как источник progress и отдельную композицию: face 3.5×6, camera (0,0,9). H.rotation=(0,0,0), position=(0,0,−5); intro=clamp(scrollY/viewportHeight,0,1); progress=max(0,(scrollY/viewportHeight−1)/1.5), если программная навигация не добавляет offset. Высота spacer=(1.5·projectCount+1)·viewportHeight; canvas fixed. Итоговый H.scale=coverScale·scale(f)·(.5+.5·intro). Не переносить desktop wheel-lock на touchscreen. Для каждого шага отдели целую часть k = floor(progress) и долю f = progress−k. Определи scale(f): 1 при f<0.5; mix(1,0.5,(f−0.5)/0.1) при 0.5≤f<0.6; 0.5 при 0.6≤f<0.9; mix(0.5,1,(f−0.9)/0.1) при f≥0.9. Определи turn(f)=0 при f<0.6; (f−0.6)/0.3 при 0.6≤f<0.9; 1 далее. rotation.x=(k+turn(f))·π/2. Это передаёт кодово подтверждённую структуру hold → shrink → turn → grow; указанные кусочно-линейные зависимости повторяют функцию setMobileProgress. Не добавляй произвольные easing на каждый участок, если это ломает привязку к обратному скроллу.

Упрощённая адаптация для слабых устройств: нативная вертикальная лента статичных карточек с устойчивым aspect ratio. Название и действие открытия видимы постоянно; весь контент доступен без WebGL.

Прими единый breakpoint 768 px в CSS и JS, устранив различие <768 и ≤768 исходника; затем проверь реальные ограничения текста и медиа. Используй 100svh/dvh осознанно, учитывай safe-area и изменение браузерной панели, не рассчитывай высоту только по старому innerHeight.

При prefers-reduced-motion показывай активную работу без пространственного поворота/параллакса. Смена мгновенная либо fade 0.12–0.18 s; все кнопки и контент остаются. Системная настройка должна отслеживаться и при изменении во время сеанса. Не делай reduced-motion пустым или менее функциональным режимом.

Производительность и устойчивость

- Один requestAnimationFrame/render loop. GSAP и ручной lerp не управляют одной величиной одновременно.
- DPR ограничить до min(devicePixelRatio, 1.5–2); на слабых мобильных устройствах можно ниже.
- Не держать запущенными все видео: текущее играет, соседнее предзагружено, остальные paused. playsInline/muted; отклонение autoplay обрабатывать постером.
- Пауза при document.hidden и вне viewport; освободить texture/material/geometry/video/listeners при unmount.
- Не вызывать React setState каждый кадр. Движение в refs/scene objects; DOM-статус менять на дискретных переходах.
- Текстуры ограничить разумным разрешением; задать размеры до загрузки. Ошибка одного файла не ломает всю сцену.
- При webglcontextlost перейти в fallback или восстановить состояние без потери контента. Не повторять наблюдавшийся у источника белый экран.

Критерии приёмки

1. Один wheel-жест даёт один логический переход; длинный инерционный хвост не прокручивает несколько работ.
2. Быстрые повторные next/prev не рассинхронизируют грань, заголовок, метаданные и кнопку.
3. Цикл проходит число проектов, отличное от четырёх; переход последняя → первая и обратный корректны.
4. При раскрытии, закрытии, resize и смене ориентации сохраняется выбранная работа; нет внезапного прыжка к первой.
5. Проверены 1440×900, 1024×768, 390×844 и 360×800, отдельно keyboard, touch и reduced-motion. Не заявлять проверенные размеры без фактического теста.
6. Контент остаётся доступен без WebGL, при ошибке текстуры и при запрещённом autoplay.
7. Desktop сцена укладывается в бюджет около 16.7 ms/frame на целевом тестовом устройстве; сообщить устройство и реальные измерения, а не обещать универсальные 60 fps.
8. В проекте не скопированы авторские медиа, тексты, названия, логотипы и фирменное оформление источника.
9. README разделяет реализованные, проверенные и оставшиеся ограничения. Итог приложить с последовательными скриншотами рабочих состояний и короткой записью движения, если среда поддерживает её.
