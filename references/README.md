# Библиотека эффектов сайтов Tatarin

Разборы сайтов-референсов, собственные применения, код эффектов и задания для Codex. Можно дать Codex название папки или URL каталога и попросить повторить механику в текущем сайте.

Начните с [каталога](CATALOG.md). Для каждого эффекта есть README.md, analysis.md, codex-prompt.md, implementation.md и provenance.json. Пять эффектов содержат исходники собственного применения; Belen Jones пока содержит анализ и ТЗ.

## Как попросить Codex

> Посмотри эффект pacome-spiral в https://github.com/garifulinandrej183-lang/tatarin-branding/tree/main/references . Прочитай README, analysis, codex-prompt и implementation этой папки. Изучи сохранённый код и повтори механику спирали в разделе работ моего текущего сайта. Используй мои карточки и текущий стек. Сохрани меню, контакты и другие работающие разделы. Проверь desktop, touch, паузу, обратное движение и reduced motion. Не копируй оформление и контент референса.

Аналогично можно указать alphabet-symbols, podium-scroll, helloshivam-fluid, quartr-portrait или belen-gallery. Подробный рабочий порядок: [CODEX_GUIDE.md](CODEX_GUIDE.md).

## Что означает наличие кода

Исходники сохранены по конкретным commit собственных опубликованных сайтов. Это ядро и контекст интеграции, не npm-пакет и не готовая универсальная библиотека. Код не отлаживается при архивировании под каждый возможный target. Медиа заменить своими; адаптировать пути, контейнеры и зависимости. Лицензии внешних алгоритмов сохранять.

Исторический анализ может описывать иной renderer, чем собственная адаптация. Например, Quartr применён на Canvas 2D; Podium адаптирован через SVG/DOM. Такое отличие указано в implementation.md.

[Результаты проверок](VALIDATION.md) отделяют тесты логики от визуальной проверки на реальном устройстве. Наличие ссылки на Site не требует публикации нового сайта или изменения прав доступа.

## Как добавлять новые разборы

1. Создать effects/<короткий-id>/ из [шаблона](templates/EFFECT_TEMPLATE.md).
2. Сохранить полный анализ и самостоятельное ТЗ, источник, дату и границы проверенного.
3. После применения сохранить ядро, необходимые DOM/CSS-контракты, зависимости, source commit и реальные результаты проверок.
4. Добавить запись в catalog.json и CATALOG.md; расширять существующий эффект, если это следующая итерация той же механики.
5. Исправления и ограничения записывать рядом с кодом. Применение помечать успешным только с конкретной версией и фактическими проверками.
